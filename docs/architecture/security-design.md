# 安全设计

当前控制与问题记录在 [current-state-audit.md](current-state-audit.md) 的安全章节。本文规定目标边界和最小修复顺序。修复要单独提交，并且先用现有只读行为做回归。

## 信任边界

| 区域 | 信任 |
| --- | --- |
| 角色提示词、评分器、已注册数据源配置 | 本机开发者维护，不从模型输出加载 |
| 用户问题、BIRD evidence、模型回复、数据库单元格 | 不可信内容 |
| `db_id` 到文件或连接的映射 | 只存在于服务端 |
| 参考 SQL 与完整评分结果 | 只存在于评测器 |
| 本地令牌和数据库口令 | 只存在于仓库外配置，禁止进入 trace、审计详情和日志 |

模型可以提议 SQL。它不能选择文件系统路径、切换 `query_only`、加载扩展或把参考 SQL 要进上下文。

## 权限

第一版本地进程仍只有一个操作者。在引入 User 之后：

- 每个 API 先解析身份，再按 Membership 和 `DataSourceGrant` 授权。
- `analyst` 只能读自己的 Conversation、Message 和红acted 结果。
- `developer` 才能读原始 trace、检查点和 `evaluation-evidence.json`。
- 数据源注册是 `owner` 动作，并写 AuditEvent。
- 运行 ID 即使被猜中，也要检查所有权。S6 要求使用完整 UUID，不能把不可猜测当作授权。

监听地址保持 `127.0.0.1`。配置若要求其他地址，进程拒绝启动。这是对 S1 的约束，避免“先加了用户表、却把端口暴露出去”。

## SQL Policy Engine

策略引擎包在现有工具外面。`SQLiteTools` 继续执行已经通过策略的语句，保留 `mode=ro`、`query_only`、authorizer、长度限制和进度超时。

策略输入是 SQL 文本、`db_id` 和调用目的（编译、执行、诊断、评分）。策略输出是允许或拒绝，加原因码。

强制模式目标：

1. 恰好一条语句。
2. 语句类是查询：`SELECT`、`WITH ... SELECT`，以及今天编译路径使用的 `EXPLAIN` 只出现在工具内部，不接受模型直接提交 `EXPLAIN`。
3. 拒绝 `ATTACH`、`DETACH`、`PRAGMA`、DML、DDL 和事务控制。
4. 函数使用白名单。白名单覆盖现有测试和 BIRD 常见 SQL 所需的普通函数，而不是在三个危险名字之外全部放行。
5. 标识符只作为 SQL 文本的一部分。路径类参数在工具入口就被拒绝。

观察模式先记录会被拒绝的语句，仍调用现有工具。这样可以用真实 trace 核对白名单是否误伤，而不改变当前结果。切到强制模式是独立 PR，必须包含：

- `DELETE`、多语句、`ATTACH` 被拒绝且库文件不变。
- 现有可执行 `SELECT` 夹具仍返回相同预览。
- 诊断器的 `NOT IN` 探针仍能运行它自己构造的只读 `EXISTS` 查询。

评分器的 `full_result_details()` 走同一策略。策略拒绝不等于答案得分 0；它是运行错误，保持“环境失败不当成答错”的现有规则。

PostgreSQL 和 MySQL 以后使用数据库侧的只读角色、语句超时和单语句执行。应用侧策略仍先分类。方言解析使用已依赖的 `sqlglot`，解析失败则拒绝执行。解析失败不用于给 BIRD 打 0 分。

## 网络安全

保持今天已经测试过的控制：

- Host 必须是 `127.0.0.1:<port>`。
- POST 的 Origin 必须是同一源。
- 不发送 CORS 允许头。
- 请求体上限。
- CSP 与 `nosniff`。

新增：

- 本地令牌用常量时间比较。错误响应不区分“未提供”和“错误”，避免给本机扫描脚本额外信息；日志只记 `auth.denied`。
- 令牌通过请求头传递，不放进 URL，避免进入访问日志。
- 上游模型只允许回环 Ollama，沿用 `LocalOllamaModel` 的主机检查。DeepSeek 仍只在显式命令里使用，网页不调用。
- 测试套件继续依赖 `conftest.py` 的网络审计钩子。

不在本地回环上引入 TLS。远程部署不在本次路线内；若要远程访问，需要新的威胁模型，而不是把当前 HTTP 直接绑到公网。

## 查询预算

把现有分散限额收成一次运行的预算对象，默认值取今天的网页值：

| 项目 | 当前来源 | 目标默认 |
| --- | --- | --- |
| 问题长度 | `start()` 1–4000 | 4000 字 |
| 活动任务 | 每进程 1 个 | 每进程 1 个，直到有队列设计 |
| 修复次数 | `max_repairs=1` | 1 |
| 工具超时 | 网页 30 秒 | 30 秒 |
| 预览 | 5 行、12 列、160 字 | 不变 |
| 类型样本 | 1,000 行 | 不变 |
| 评分上限 | 100,000 行或 32MB | 不变；超出是评测失败 |
| 模型请求 | Ollama 600 秒、非流式 | 不变，直到取消 PR |
| 生成长度 | `generation_budget()` | 不改函数 |

本地网页没有 DeepSeek `Ledger`。不要把付费账本套到本地运行上。若以后网页可以选付费模型，必须沿用“未知 usage 则停止下一次请求”的规则，并且默认不启用。

停止仍是协作式。最小增强是停止时关闭正在使用的 HTTP 客户端，使 600 秒上限不再成为唯一的取消手段。

## Prompt injection

目标是限制注入的后果，而不是宣称模型不会服从恶意句子。

- 不可信问题保持在用户内容中。记忆摘录、schema 样本和单元格同样视为不可信。
- 工具参数由服务端绑定 `db_id`。模型输出里的路径、URL 和 `ATTACH` 名字不解释为连接指令。
- 策略引擎限制语句类和函数，使“忽略说明并写文件”在工具层失败。
- 结果投影限制返回给用户和下一轮记忆的数据量。
- 不增加一个会改写 SQL 的自动安全模型。那会改变三角色行为。

系统提示词的加固文字若要修改，必须单独评审。本设计不要求改 `_decomposer_prompt()` 的现有句子。

## 敏感数据

分级：

| 数据 | 用户视图 | 开发者视图 | 模型下一轮 |
| --- | --- | --- | --- |
| 问题文本 | 可见 | 可见 | 仅当前对话摘录 |
| 采纳的 SQL | 可折叠可见 | 可见 | 摘录开启时有界可见 |
| 预览行 | 现有上限 | 现有上限 | 不进入摘录 |
| schema 样本 | 不可见 | trace 中可见 | 仅当前轮检索，沿用现有上限 |
| 参考 SQL | 不可见 | 仅哈希和评分摘要 | 不可见 |
| 令牌和口令 | 不可见 | 不可见 | 不可见 |

S2 的最小修复是给 `/api/run` 增加投影参数或单独的用户 DTO，而不是立刻删除磁盘上的研究 trace。现有观察台测试继续读完整工件。

日志沿用 DeepSeek 路径的规则：异常文本不包含请求头。新增认证日志只记动作和结果。

## 业务库与应用库

用户 SQLite 只读打开。应用不执行 `CREATE`、`INSERT` 或 `VACUUM`。应用自己的 `workspace.sqlite` 是可写的，放在输出目录，权限依赖本机文件系统。它不存放业务行，只存放元数据和审计摘要。

打开 SQLite 前保留文件头检查。网络数据库上线前还要增加：TLS、只读账号、禁止超级用户、连接超时，以及测试用的假驱动。没有这些之前，`kind` 为 `postgres` 或 `mysql` 的数据源保持 `unavailable`。

## 最小修复顺序

1. 补执行路径的多语句回归测试，只断言现有 `execute_sql_readonly` 返回错误且文件不变。
2. 用户 DTO 脱敏，观察台响应保持不变。
3. 本地令牌，仅当实现多用户或非个人机器使用时启用；个人默认配置可以在文档中声明“本机可信”。
4. 策略引擎观察模式。
5. 在夹具证明没有误伤后，再开强制模式。

第 1 步不改变产品行为。第 2 步只改变用户页所读的 JSON 形状时，必须同步改 `test_user_ui.cjs` 的夹具；观察台夹具保持旧形状。
