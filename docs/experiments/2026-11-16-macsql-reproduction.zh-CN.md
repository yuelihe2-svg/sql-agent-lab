# MAC-SQL 原方法复现：DeepSeek 同一 50 题对照报告

本轮复现模式 D 答对 **20/50（40%）**，低于之前应用三角色 C 的 **24/50（48%）**，也低于单角色 A、B 的 **25/50（50%）**。D 的估算费用约为 C 的 **3.30 倍**。这次结果不支持把整套原版配置替换为应用默认工作流。

但 Refiner 在本轮确实发挥了作用：10 道题触发修复，其中 **6 道从初始 SQL 错误变为最终正确**。两项结论并不冲突：修复环节能挽回部分错误，整套配置的初始生成和最终表现仍可能较差。

这是同一固定样本上的历史配对比较，不是原论文分数复现，也不是只改变一个角色的消融。所有真实结果已经保存，未根据表现重跑题目或调整配置。

## 2. 实验设置

复现代码运行提交为 `d12d57d`，官方方法代码固定为 `31a9df5e0d520be4769be57a4b9022e5e34a14f4`。旧 A/B/C 运行提交为 `3da66ed`；旧协议和全部 150 份结果文件的哈希均再次核验，没有覆盖或重跑。

沿用上一轮冻结的 **50 个题号、顺序、问题文本、evidence 和参考答案版本**。样本来自同一份 BIRD Mini-Dev 快照，涉及 11 个数据库；原始难度标签为 47 challenging、2 moderate、1 simple。没有重新抽样。原版固定 few-shot 提示词中未发现这 50 道问题的逐字重复；这不是对近义改写或模型训练数据重叠的完整排查。

模型继续使用 `deepseek-flash`，官方标注版本为 DeepSeek-V4.1-Flash-1017；实际返回标识均为 `deepseek-flash`。D 按原版调用设置使用 temperature=0.1，A/B/C 为 0；均关闭 thinking。服务端未提供权重哈希，不能据别名断言不同时间的底层权重完全相同。[模型与价格来源](https://api-docs.deepseek.com/quick_start/pricing/)

| 设置 | 角色与生成方式 | 修复规则 | 本轮是否新增调用 |
|---|---|---|---|
| A | 单角色、通用提示词，一次生成 | 不修复 | 否，复用历史 50 题 |
| B | 与 A 相同的初次生成 | 允许原应用执行/类型反馈修复；旧批次实际未触发 | 否，复用历史 50 题 |
| C | 现有应用的条件式三角色 | 原应用规则；旧批次 Refiner 未触发 | 否，复用历史 50 题 |
| D | 作者原版提示词、两个 Decomposer 示例、按列数触发 Selector | 执行错误、空结果、前五行出现 NULL；至多三轮 | 是，新增 50 题 |

D 每次最多输出 3200 tokens，提示词最多 100000 UTF-8 字节；实际预检的完整初始提示词最大为 17854 字节。每题最多 5 次模型请求；不自动重试、不追加修复、不中途扩大预算。一次输出截断按失败计入 50 题分母。

D 使用作者元数据和频率排序取值，不使用应用的额外字段说明、检索或值查询，也不添加类型检查、语义复核和候选回退。只读保护保持开启。工作流执行超时上限为 120 秒；独立评分仍使用与旧组相同的 30 秒和结果规模限制。

所有组使用同一独立评分口径：执行预测 SQL 与参考 SQL，比较完整结果集合，忽略行顺序和重复行，**保留列顺序**。它不是官方 BIRD 榜单评分器，也不完整验证排序和重复次数需求。参考答案只用于后置评测，不进入 Agent 输入。

## 5. Trace 告诉我们三个角色做了什么

### Selector：发生了筛选，但还不能证明提高正确率

D 在 46/50 题调用 Selector，46 次均解析成功，没有回退完整 schema；其中 45 题减少列数，1 题列数未变。按原版行为，所有元数据表仍保留，`drop_all` 保留前六列，不是真正删除整表。

对这 46 题，把筛选后的 Decomposer 提示词与同一题、同一原版模板的完整 schema 文本比较，UTF-8 字节总量由 532736 降至 399343，减少 **25.04%**。这是文本长度比较，不是实测的“关闭 Selector 后模型 token 数”。Selector 自身消耗 143419 输入、4459 输出 tokens，估算费用 $0.04838，约占 D 总费用的 32%。没有无 Selector 的同配置实验，不能声称这笔开销换来了准确率收益。

一个仍然失败的“所有球员平均值”案例中，Selector 已保留完整球员表，Decomposer 仍只统计实际出场球员，漏掉零次出场者。保留表不等于模型会正确理解统计总体，也不能把所有错误都归咎于 Selector。

### Decomposer：确实进行分解，但分解不保证最终 SQL 完整

50 次调用中有 49 次正常结束，1 次反复讨论诊断取值直到 3200 tokens 上限，未交付可接受的最终 SQL。正常回复中，46 次含多个 SQL 围栏、3 次只有一个；原方法只执行最后一个围栏。

一个问题同时要求“比例”和“人数”，模型分别给出了多个子问题 SQL，却没有生成合并两项结果的最终 SQL。最后一段只计算人数，独立评测发现应有两列而实际只有一列。SQL 能执行、结果非空，原版 Refiner 不会介入。这个案例不是“完全没生成 SQL”，而是**最后一个 SQL 没有回答完整问题**。

其他可执行错误包括：把人数算成记录数、连接一对多明细后重复计数、缩窄地点匹配、额外添加并未要求的分类条件、遗漏零参与者。这些错误不会必然触发执行修复。

### Refiner：本轮有直接可核验的收益，也有明确盲区

10 道题共调用 Refiner 18 次。触发原因按轮次计数为：10 次空结果、5 次 NULL、3 次缺失字段错误。

在 Agent 已结束之后，使用同一参考答案和评分器重新评估这些题的初始 SQL 与每个修复候选，没有再次调用模型，参考答案也没有回流到 Agent：

| 结果 | 题数 |
|---|---:|
| 初始错误 → 最终正确 | 6 |
| 初始错误 → 最终仍错误 | 4 |
| 初始正确 → 最终错误 | 0 |

其余未修复题的最终 SQL 就是初始 SQL；将截断任务继续算作失败，本批轨迹中初始生成正确数为 **14/50**，修复后为 **20/50**。这是同一批已生成候选的后置轨迹分解，不能替代重新随机运行“去掉 Refiner”的独立消融。

成功修复包括：纠正不存在的字段/别名、为带连字符的字段补充引用、纠正日期字符串格式、把错误的赛道名称条件改到赛事表、修复学校标识符前导零、按题意选择合适的历史快照。

失败案例说明了原版 NULL 启发式的风险：某日期字段实际保存为紧凑年月，模型错误使用日期解析函数得到 NULL；修复没有识别格式，最后用 `COALESCE(..., 0)` 把 NULL 变成数值。工作流因此接受结果，答案仍错。另一个诊断名称案例持续使用猜测的缩写，三轮只添加非空条件，没有纠正真正的取值。

三道题达到第三次修复上限，最后候选没有再经过 Agent 执行检查；**独立评测仍执行了这些最终 SQL**，全部判错。报告没有用前一轮执行反馈冒充最终候选结果。

## 6. 区分评分不匹配与业务语义错误

一题涉及排序编号和多列统计。D 的结果按既定评分器判错，但后置诊断仅把最后的排名列移到第一列，340 行结果集合即与参考结果完全一致。此例属于本评分口径下的列顺序不匹配，不宜笼统说成统计内容错误。

这项诊断没有修改 SQL、既定分数或总表。若要改变评分契约，应对所有设置统一重评，不能只给 D 特例加分。即使仅作非正式敏感性参考，把这一题视为内容一致，D 也只是 21/50，仍低于 C 的 24/50。

## 7. 能得出的结论与下一步

1. **目前保留现有应用工作流作为默认。** D 在同一 50 题上更贵、更慢，最终正确数更少；本轮没有支持整体替换的证据。
2. **Refiner 值得继续研究。** 本轮明确修好了 6 题，但“空/NULL 必须修”过于粗糙；避免用零掩盖格式错误、围绕执行反馈诊断根因是后续改进方向，不应伪装成原版复现结果。
3. **下一次实验优先隔离变量。** 在同一生成提示词、模型参数、schema 表示和预算下，分别开关 Selector、Refiner，或单独比较原版分解与强制完整最终 SQL 的输出契约。正式运行前预先固定配置和重复次数，不根据本轮个别题号编写规则。

限制包括：历史组与新组不是同期随机交错；temperature、few-shot、schema/取值、检索、修复规则、输出预算和执行超时同时变化；样本小且复杂题占比高；每题仅一次生成；模型与论文不同；评测器也不是官方脚本。结果支持的是**本机固定数据与这些配置下的观察**，不能判断原论文结论真伪，不能分离每个变化的因果贡献。
